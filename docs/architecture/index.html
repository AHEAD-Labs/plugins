What to build, in order

  1. Done today: signing, review gate, CI deploy. Releases are signed with a real key and verified, main needs a PR and a passing check, and a merge deploys to AWS from CI. Still open from this step: a CI identity so the pipeline can also run the real Entra check, and a review team.
  2. Azure agent: gateway built and verified. Entra token check, allowed-callers list, suspension and audit sit in front of the agent, and a real on-behalf-of call reaches it. Still open: register it through the pipeline as an agent capability, call it from the AWS MCP, and close the agent's own public ingress.
  3. Add SPIFFE. Stand up a sandbox trust domain, split the backend from the function, and make the gateway-to-backend call use a workload identity. AWS first, then the agent.
  4. MuleSoft platform. Register a capability in Agent Fabric and publish it through Omni Gateway with the Entra check. Needs an Anypoint sandbox and an answer on self-hosting; see docs/mulesoft.md.
  5. Give local MCP real identity. Sign the user in with Entra and add a way to withdraw a package already installed on a laptop.
  6. Plugin access by group. Entra groups decide who sees and uses each capability; tools/list follows the user.
  7. Databricks. A governed read path that passes the signed-in user through and is audited.
  8. One audit record and Geordie. A common event format on every platform, one suspension control for all of them, and Geordie reading the telemetry.

Not shown, because nothing is built: KPaaS gateway, A2A, multi-region. Codex-to-OpenAI details that depend on decision D8 (how plugins reach OpenAI) are unconfirmed.
